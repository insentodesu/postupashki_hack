# MVP — небольшая end-to-end marketing measurement platform, которая связывает:

## campaign → placement → creative → touch → lead → order → revenue → ROMI

## **Компоненты:**

- **Ad Registry** — создание кампании/размещения: канал, креатив, стоимость, курс, дата. Генерация уникальной Telegram deep link.
- **Tracking Bot** — фиксирует переход по ссылке, хеширует Telegram ID, создаёт touch и lead.
- **Payment Adapter** — импорт base.xlsx и ручное добавление тестовой оплаты; позже заменяется интеграцией с CRM/платёжной системой.
- **Attribution Engine** — связывает оплату с рекламным касанием. Методы: deterministic, self-reported, modelled, unknown. Для MVP — last eligible touch с окном 30 дней.
- **ROMI Engine** — считает spend, revenue, conversion, CAC и ROMI. Если нет переменных затрат, используем revenue-based ROMI и явно указываем ограничение.
- **Dashboard** — показывает воронку touch → lead → order, результаты по placement, ROMI, confidence и долю unknown.

## **Демосценарий:**

## создать placement → получить ссылку → перейти в бота → создать touch/lead → добавить оплату → увидеть attribution и ROMI

Исторические продажи из base.xlsx используем для transaction layer и EDA, но не придумываем для них рекламную атрибуцию без идентификаторов.

Обязательно сделать offline demo mode, чтобы переход, лид и оплату можно было симулировать без Telegram и интернета.

MVP готов, когда вся цепочка работает на одном тестовом пользователе и заказ без tracking остаётся unknown, а не приписывается рекламе.

# Как будем связывать пользователя
Идея: дать каждому переходу из рекламы свой уникальный номер и провести его до оплаты.

<img width="2335" height="389" alt="image" src="https://github.com/user-attachments/assets/5a3cab3e-5620-41fb-9546-1e37720d99bc" />

## **Что делаем:**

- человек кликает по рекламе;
- по ссылке получает уникальный ID;
- этот ID передаём в Telegram;
- когда человек становится лидом, сохраняем связь с этим ID;
- при оплате видим, из какой рекламы пришёл клиент.

## Если точную связь построить нельзя

Например, человек просто читал Telegram-канал и потом сам написал менеджеру.

**Тогда:**
- не пытаемся угадать конкретного пользователя;
- считаем такие случаи отдельно;
- эффект рекламы оцениваем по группам пользователей и через A/B-тесты.
## **Итог**: где можем — связываем путь пользователя точно, где не можем — оцениваем влияние рекламы статистически.
